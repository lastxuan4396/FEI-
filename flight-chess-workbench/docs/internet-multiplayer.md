# Render 双人联机

前端、七个任务出牌版本与普通棋盘房间运行在同一个 Node 服务；HTTPS 由 Render 提供。邀请链接包含另一位玩家的独立凭证。不要公开分享房间链接。

建房 → 复制邀请 → 对方在自己的设备打开。各自保留链接，刷新重新恢复身份。秘密选择在双方提交之前由服务端隐藏。服务器验证操作与回合，操作编号保证断线重试不会重复结算。

有时长/次数/持续效果的任务随房间状态保存。任务计时开始采用服务器时间；独立持续任务仍可与下一次抽取并行。原图整理地图可以线上打开与导入；RapidOCR 仅保留在本地工作台，不在免费服务运行。

## 启动

`npm ci && npm run build && npm run serve:online`

生产环境需设置 `REDIS_URL`；`REDIS_PREFIX` 默认 `paired-workbench-v1`，与旧版 `flightchess` 隔离。Render 未设置 Redis 会拒绝启动，不会悄悄退回临时内存。端口采用 `$PORT`，健康端点 `/healthz`。本机不设置 Redis 时写入 `work/online-rooms/`，可以用 `ROOM_DIRECTORY` 指定独立测试目录。

## 免费服务的实际边界

Render 免费网页服务会休眠，首次打开可能等待唤醒。Key Value 与网页进程分离，所以网页重启或重新部署后能继续房间。免费 Key Value 没有磁盘持久化；Key Value 自身重启可能清空房间，不承诺永久存档。需要长期保留时可自行导出本机存档，或另行选择有持久化的数据库。未开通任何付费套餐。

房间七天无操作失效。默认最多30个出牌房间；存储总量有上限，保存失败返回可重试错误。数据使用隔离前缀，公网不开放 Key Value 连接。
